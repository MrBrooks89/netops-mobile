# Android release runbook

Everything needed to cut, verify and ship an Android build of NetOps Toolkit.
iOS is deferred until an Apple developer account exists (see
[IOS_PARITY.md](IOS_PARITY.md) and ADR-010 for the groundwork that is already
in place).

## Identity — decide once, then never

| Thing | Value | Notes |
|---|---|---|
| Application ID | `tech.mrbrooks.netops` | **Permanent after the first Play upload.** Changing it later means a new listing and losing installs. |
| Display name | NetOps Toolkit | `expo.name` → launcher label and store listing default. |
| Slug | `netops-toolkit` | EAS project key; also the `exp+netops-toolkit://` dev-client scheme. |
| Deep-link scheme | `netops://` | Unchanged by the slug; `netops://tool/<id>` opens a tool. |
| Version | `0.1.0` (`versionName`) | Human-facing; bump per release. |
| versionCode | `1` | Play requires a strictly increasing integer. `eas.json` sets `autoIncrement: true` for the `production` profile, so EAS manages it; a local build uses the value in `app.json`. |

## Build

```bash
# Dev client (what day-to-day work uses)
scripts/dev.sh install        # debug APK + install on the emulator

# Release, local: per-ABI APKs + a universal APK
export JAVA_HOME=$PWD/.tools/opt/jdk-21.0.9+10 ANDROID_HOME=$PWD/.tools/android-sdk
(cd android && ./gradlew assembleRelease)
ls android/app/build/outputs/apk/release/
#   app-arm64-v8a-release.apk    38.0 MB   ← what a phone installs
#   app-x86_64-release.apk       38.5 MB   ← emulator
#   app-armeabi-v7a-release.apk  31.0 MB
#   app-x86-release.apk          39.0 MB
#   app-universal-release.apk   100.5 MB   ← "send it to anyone"

# Release bundle for Play
(cd android && ./gradlew bundleRelease)
#   android/app/build/outputs/bundle/release/app-release.aab   73.4 MB
#   Play serves ~38 MB of that per device (it splits by ABI), so the download
#   the user sees is the arm64 figure above, not the bundle size.
```

> **Split APKs are scoped to release *APK* builds on purpose.** AGP refuses to
> build an app bundle while multiple APK outputs exist ("Multiple
> shrunk-resources files found … Please disable building multiple APKs when
> building an Android app bundle"), and `scripts/dev.sh install` needs the
> single debug APK. `plugins/withAbiSplits.js` therefore enables splits only when
> the requested tasks contain `assembleRelease` and no `bundle` task. Both were
> verified after the fact: `bundleRelease` produces the AAB, `assembleDebug`
> still produces one `app-debug.apk`.

`android/` is generated by `expo prebuild` and gitignored (ADR-001). Two
plugins shape the release build:

- **`expo-build-properties`** (`app.json`) turns on R8 minification and resource
  shrinking. Without it Expo leaves minify off, and the DEX alone was 46.5 MB;
  it is 14.8 MB with it on.
- **`plugins/withAbiSplits.js`** asks AGP for per-ABI split APKs on release APK
  builds only (see the note above). The plugin API cannot express this, and
  without it the sideload artifact carries four architectures' native libraries
  (84 MB of the original 111 MB).

Measured, in this repo, before and after: universal APK 111 MB → 100.5 MB
(R8 alone), arm64 APK 38.0 MB, AAB 73.4 MB. DEX 46.5 MB → 14.8 MB.

## Verification gates — all of these before a release

```bash
export ANDROID_HOME=$PWD/.tools/android-sdk

# 1. The usual gate
pnpm typecheck && pnpm lint && pnpm check:platform && pnpm format:check && pnpm test:coverage

# 2. The built artifact's manifest (package id, versionCode, backup off, no
#    dev permissions, required permissions present, cleartext on per ADR-007)
node scripts/check-android-manifest.mjs

# 3. The app actually runs: installs, launches with no dev server, renders the
#    dashboard, answers with a native capability, renders a pure tool, and
#    completes a TCP attempt without dying (R8 check). Picks the split matching
#    the attached device's ABI.
scripts/android-release-smoke.sh
```

Both scripts exist because the manifest and the minified runtime are where
release-only defects live, and both were found by hand the first time:
`SYSTEM_ALERT_WINDOW` merged in from `expo-dev-client`, and
`allowBackup=true` — which would have uploaded the app's SQLite data to the
user's Google Drive while the onboarding card promises "results stay on this
device".

## Signing and distribution

**Sideload / internal testing.** A local `assembleRelease` is signed with the
debug keystore (Expo's template default), so the APK installs on any device with
"install unknown apps" allowed. That is fine for sharing with a colleague and
**not** acceptable for Play.

**Google Play.** Use EAS, which manages the upload keystore for you:

```bash
npx eas-cli login                  # your Expo account
npx eas-cli build -p android --profile production   # AAB, auto-increments versionCode
npx eas-cli submit -p android --profile production  # upload to Play
```

`eas.json` already defines `development` (dev client), `preview` (internal APK)
and `production` (AAB + `autoIncrement`). Running `eas build` the first time
creates the EAS project and prompts for a keystore — let EAS generate it and
keep the credentials in your Expo account rather than in this repo (the
`.gitignore` already excludes `*.jks`, `*.keystore`, `*.p8`, `*.p12`).

### Play checklist

- [ ] **Data safety form.** The app collects nothing and sends no telemetry;
      history, saved hosts/networks and settings stay in local SQLite. With
      `allowBackup: false` the platform no longer copies that data to Google
      Drive, so "stays on device" is accurate.
- [ ] **Privacy policy URL.** Even with no collection, a short policy is
      expected for a network tool; it can state the above in a page.
- [ ] **Content rating** and **target audience**: tools category, no ads, no
      user-generated content.
- [ ] **Authorized-use framing** stays prominent (dashboard onboarding, both
      scan screens): Play review looks closely at scanning tools, and this copy
      is also the honest UX.
- [ ] **Foreground service declaration**: not needed — no background work
      ships.
- [ ] **targetSdk 37 later**: when Play requires it, Android enforces Local
      Network Protections and every LAN tool needs `ACCESS_LOCAL_NETWORK` plus
      a runtime rationale. ADR-009 has the exact plan; the symptom to expect if
      it is skipped is "everything times out", not a permission error.

## Permissions in the release manifest (and why)

| Permission | Needed by |
|---|---|
| `INTERNET` | every networked tool |
| `ACCESS_NETWORK_STATE` | transports, gateway/DNS via `LinkProperties`, offline detection |
| `ACCESS_WIFI_STATE` | Wi-Fi basics |
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | SSID/BSSID, channel/frequency (runtime request, with the "why location?" explainer) |
| `CHANGE_WIFI_MULTICAST_STATE` | the mDNS browse during LAN discovery |
| `READ/WRITE_EXTERNAL_STORAGE` (`maxSdkVersion=32`) | share sheet on older Android only |
| ~~`SYSTEM_ALERT_WINDOW`~~ | **blocked** — dev-client artifact, never used |

`usesCleartextTraffic="true"` is deliberate app-wide (ADR-007): the HTTP
diagnostics tool must reach plain `http://` targets and neither OS supports
scoping that per request.

## Real-device pass (still outstanding)

Everything verified so far is the emulator (and the CI simulator for iOS). The
emulator's user-mode network silently drops every unused address, which is the
opposite of a normal LAN. Before shipping, run the plan's §15 matrix on real
hardware:

- [ ] LAN sweep on a real /24: coverage within the 20 s budget, and sweep
      timing when hosts answer with RST rather than silence.
- [ ] Port scan against a **silently dropping** firewall: how long 100 ports
      actually take (the 3 s default timeout and the socket library's 2-thread
      connect pool set the floor), and whether the default should be lower.
- [ ] Wi-Fi SSID/BSSID with Location Services **off**, then on; permission
      denial then re-grant from Settings.
- [ ] mDNS discovery with a real responder (printer, Chromecast, HomePod).
- [ ] Two OEM stacks (Samsung One UI, Xiaomi HyperOS) — they are the usual
      source of network-stack surprises.
- [ ] Cellular-only: tools that need LAN reachability degrade with a clear
      message rather than a hang.
- [ ] Release build on a real phone (not just the emulator): cold start, a
      full sweep, and screen-off during a scan (keep-awake should hold it).

## Deliberately not in the Android release

Background scans (no foreground service, no notifications), system-resolver
DNS (DoH only, so split-horizon names are invisible — D3), UDP scanning, SSDP,
mDNS on Android below 14, IPv6 discovery, traceroute, i18n, tablet/RTL
layouts. All are plan decisions (see `docs/IMPLEMENTATION_PLAN.md` §2 and §M9+),
not omissions.
