# ADR-001: CNG + dev-client from day one

**Status:** Accepted (M0)
**Deciders:** planning agent + repo owner
**Date:** 2026-09-11 (M0 implementation)

## Context

Expo offers multiple workflows: Expo Go, and Continuous Native Generation (CNG)
with a development build ("dev client"). The implementation plan (D1, §20)
flags this as the first architectural decision to resolve.

The project roadmap (M4+) requires native Android modules: TCP sockets for
scanning, an ICMP/TLS/Wi-Fi Expo module, and `react-native-tcp-socket`-style
community libs. Expo Go cannot load custom native code, so a workflow
migration would be forced mid-project — historically a painful, error-prone
process that rewrites git history expectations around `android/`/`ios/`.

## Decision

1. Use **CNG**: `app.json` (later `app.config.ts`) is the native source of
   truth. `android/`/`ios/` are generated by `npx expo prebuild` and are
   **gitignored** (never committed, never hand-edited without a config-plugin
   or plugin reason).
2. Use **dev-client builds** for all device/simulator testing from M0 on,
   even though M0–M3 are pure JS and could run in Expo Go.
3. Local Fedora builds use the staged JDK 21 (`.tools/opt/jdk-21.0.9+10`) —
   never the system Java 25, which Gradle plugin versions do not expect.
   EAS cloud builds are the fallback path and work regardless of host OS.

## Consequences

- **Pros:** no workflow migration ever; native deps can land in M4 without
  disruption; prebuild regeneratability is an enforced discipline (M0
  acceptance criterion: `prebuild` runs clean, twice, with no diff).
- **Cons:** every native dependency change requires a new dev-client build
  (minutes with local Gradle, ~10 min with EAS); Expo Go is not an option for
  daily dev.
- The emulator harness (`scripts/emu.sh`) + local Gradle assembleDebug covers
  device testing without EAS for day-to-day work.

## Verification (M0)

- `npx expo prebuild --platform android --clean` → success, no warnings.
- `./gradlew assembleDebug` on JDK 21 → APK builds (see M0 report).
- `git status` ignores `android/`.
